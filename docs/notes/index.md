## 一、两份文档的定位与关系

| 维度 | 总体框架（framework） | 拓扑同胚（topology） |
|---|---|---|
| 性质 | **收敛结论**：对全日研讨的整合，是行动的纲领 | **展开论证**：从一个具体问题（5 面开口盒子 ≠ 开口半球？）出发的完整技术推演 |
| 视角 | 系统级：端到端流水线 + 分阶段实现 + 数据 + 人力 + 风险 | 原理级：为什么可行、边界在哪、深水区在哪 |

**一句话关系**：framework 给出**工程蓝图**，topology 给出**可行性论证与理论护栏**；后者的「Hybrid 落地」结论直接支撑前者的整体算法框架（DL 感知 + 传统几何求解的混合范式）。

## 二、共享的核心主张（两文档一致的判断）

1. **纯端到端/纯 DL 回归几何坐标不可行**，必须「模型只输出决策（类型/分割/边界性质），几何参数由解析拟合算出」。
2. **传统几何功底是精度的最终来源**（RANSAC / 最小二乘 / 求交裁剪 / 微分几何），DL 的价值在感知与提议。
3. **拓扑先验是必需的先验**：B-rep 的合法性与欧拉公式约束必须在构造阶段强制执行。
4. **欠定处需选择或人来兜底**，而非硬算。
5. **评测必须端到端**，模块指标（如分割 mIoU）≠ B-rep 有效性。

## 四、关键技术链路（合并视角的端到端流水线）

```
输入：机械臂多视角稠密点云（位姿已知）
  │
  ├─[P0—P3 感知] DL/统计：逐点基元分割 + 类型推荐 + 参数初值     ← topology 4.3/4.4/4.6
  │
  ├─[P4 骨架构造] 解析面求交(SSI) + 边界判定三分支 + 定向 + 顶点/边/环  ← topology 6.6/6.7
  │               传统拟合(RANSAC/最小二乘) + MDL 停止 + 合并 + GlobFit 全局正则
  │
  ├─[P5 补全/提议] 规则 + 大模型：派生未见面；欠定时生成候选          ← topology 4.5 (分析即合成)
  │
  ├─[P6 装配求解] 约束传播 + 自由度记账 + 物理/装配约束              ← framework 四章
  │
  ├─[语义闭环] 双向验证 + TMS 非单调回溯 + L0—L4 一致性             ← framework 六章
  │
  ├─[主动消歧] 规划 → 补拍 → 重算                                 ← framework 七章
  │
  ├─[P7 验证] 残差回检 + 欧拉公式 V−E+F−L=2(S−G)                   ← topology 6.7
  │
  └─[P8 输出] STEP AP242 + provenance/不确定性(JSON)
```

## 五、关键技术栈缺口（待补的实现依赖）

| 环节 | 需要的库/工具 | 现状 | 备注 |
|---|---|---|---|
| 点云 IO / 基础几何 | Open3D、NumPy、SciPy | 通用可得 | 预处理、下采样、法向估计 |
| 隐式场 / 重建 | PyMCubes、scikit-image（MC）、DeepSDF 系 | 可得 | SDF 插值与 Marching Cubes |
| 网格参数化 / 变形 | libigl（ARAP、LSCM、调和参数化）、PyTorch3D | 可得 | topology 二章 ARAP 路线 |

| 全局正则优化 | GlobFit 风格优化器（CERES/g2o 或自研 LLT） | **缺口较大** | 平行/垂直/共轴/等半径/对称约束 |

**最大缺口**：① Efficient RANSAC + MDL 的工程实现与阈值标定；② GlobFit 全局正则优化的落地；③ 尺度相关公差阈值的确定（见下）。

## 六、未解决的深水区（两文档共同点名）

1. **尺度与公差**：全局正则约束尺度无关，但残差阈值 ε 的合格判定尺度相关 → 尺度统一前阈值无法定死（topology 6.10）。
2. **MDL 停止准则**：过分割是主要失败模式，MDL 权重对传感器噪声极敏感（topology 6.4 / 6.10）。
3. **GlobFit 全局优化**：从「能跑通」到「精度够用」的分水岭（topology 6.10）。
4. **「面集是否完整」**：framework 认定的唯一真难点，依赖八级派生依据 + 自由度记账。
5. **部分缺失面**：三类面中最棘手的一类，需语义与几何双向推断。
6. **sim-to-real gap**：真实扫描噪声/缺失/密度不均，决定落地必须走 Hybrid。

## 七、推荐推进次序（综合两文档）

1. **先做最小闭环（V1）**：拿典型零件（带孔+槽的方块）手工打通「分割 → RANSAC 拟合 → MDL 停止 → 合并 → GlobFit → 边界双向调整 → 欧拉验证 → 导出」全链路，标定每环阈值（topology 6.10 建议；framework 11.1 V1 路线）。
2. **再做 latent 可行性实验**：ShapeVAE 冻结 encoder + 线性探针测「平面vs曲面 / 开口vs封闭 / 尺寸回归」（topology 4.6）；用 decoder SDF 做微分几何读基元（topology 4.5）。
3. **补 DL 感知**：在 V1 的手工分片位置上训练逐点分割头 + 基元类型头，替换人工环节（framework 11.2 / topology 4.4）。
4. **最后补装配级与语义闭环**：约束传播 + TMS 回溯 + 主动补拍（framework 四/六/七章）。
5. **全程保留失败案例集，端到端评测**（framework 九章）。
